# Phase 4 — PTX backend

## Goal
`tinycu k.tc -o k.ptx` emits valid PTX that `ptxas -arch=sm_75` accepts for every valid program.

## 0. Learn first (30 min, write notes into docs/INTERVIEW_NOTES.md)
Write `vecadd.cu`, run `nvcc -ptx -arch=sm_75 vecadd.cu` and read the PTX. Map each line to
concepts: `.entry`, `.param`, `ld.param`, `cvta.to.global`, `%tid.x`, `mad.lo`, `mul.wide`,
`setp`, `@%p bra`, state spaces (.param/.global/.shared/.reg).

## 1. Module header
```
//
// Generated by TinyCU <version>
//
.version 7.0
.target sm_75          // --sm flag
.address_size 64
```
Use PTX ISA 7.0 so Colab’s driver JIT/ptxas always accepts it.

## 2. Kernel signature
```
.visible .entry saxpy(
	.param .f32 saxpy_param_0,
	.param .u64 saxpy_param_1,
	...
)
```
int→`.s32`, float→`.f32`, pointers→`.u64`.

## 3. Register mapping
Declare per kernel, counts computed after emission:
```
.reg .pred %p<NP>;  .reg .b32 %r<NR>;  .reg .f32 %f<NF>;  .reg .b64 %rd<ND>;
```
Map IR vreg → (class, index) with a simple table. Keep a comment `// %i` for named vars
(`--ptx-comments`, ON by default) — great for reading output in interviews.

## 4. Instruction selection table (implement exactly; document in docs/ARCHITECTURE.md)
| IR | PTX |
|---|---|
| param (i32/f32) | `ld.param.s32 / ld.param.f32` |
| param (ptr) | `ld.param.u64 %rdA,[..]; cvta.to.global.u64 %rdB,%rdA;` |
| sreg tid/ctaid/ntid/nctaid | `mov.u32 %r, %tid.x` / `%ctaid.x` / `%ntid.x` / `%nctaid.x` |
| add/sub/mul i32 | `add.s32 / sub.s32 / mul.lo.s32` |
| add/sub/mul f32 | `add.rn.f32 / sub.rn.f32 / mul.rn.f32` (**.rn blocks FMA contraction**) |
| div/rem i32 | `div.s32 / rem.s32` |
| div f32 | `div.rn.f32` |
| neg | `neg.s32 / neg.f32` |
| cmp i32 | `setp.{eq,ne,lt,le,gt,ge}.s32 %p, a, b` |
| cmp f32 | `setp.eq.f32`, **`setp.neu.f32`** for `!=` (unordered: true on NaN, C semantics), `setp.{lt,le,gt,ge}.f32` (ordered) |
| and/or/not i1 | `and.pred / or.pred / not.pred` |
| cvt | `cvt.rn.f32.s32` ; `cvt.rzi.s32.f32` |
| min/max/abs | `min.s32 max.s32 abs.s32 / min.f32 max.f32 abs.f32` |
| sqrt | `sqrt.rn.f32` |
| mov | `mov.{b32,f32,pred,b64}` |
| addr global | `mul.wide.s32 %rdT, %idx, 4; add.s64 %rdA, %rdBase, %rdT;` |
| load/store global | `ld.global.{s32,f32} / st.global.{s32,f32}` |
| shared array | `.shared .align 4 .b8 name[4*N];` + `mov.u64 %rd, name;` + `ld/st.shared` |
| barrier | `bar.sync 0;` |
| br / condbr / ret | `bra.uni L;` / `@%p bra Lt; bra.uni Lf;` / `ret;` |
Immediates: f32 as hex `0f3F800000` (exact bit pattern — avoids decimal round-trip bugs).
Labels: `$L__<label>` (PTX-safe chars only). Omit `bra` to the fall-through block.

## 5. Validation & stats tooling
- `tools/ptx_check.sh k.ptx` → `ptxas -arch=sm_75 -v k.ptx -o k.cubin` ; parse
  `Used N registers`, spill stores/loads, smem bytes.
- `python -m tcharness.ptxstats` → table: kernel, #PTX instrs, #regs, spills, #SASS instrs
  (`cuobjdump -sass k.cubin | grep -c '^ */\*[0-9a-f]\{4\}\*/'`), cubin ELF sections
  (`cuobjdump -elf`) — PTXAS team talking point (object files, .nv.info, .text.<kernel>).
- CI job `ptx-validate`: compile every tests/golden & tests/kernels program and run ptxas.

## Tests
- Golden `*.ptx` snapshots for all programs.
- ptxas acceptance for 100% of valid programs (CI).
- Unit tests for f32 hex immediate encoding (0.1f, -0.0, 1e-38, inf rejected at sema/lexer).

## Definition of Done
- [ ] Every valid test program → PTX accepted by ptxas sm_75 (CI job green)
- [ ] `--emit=ptx` deterministic; comments readable
- [ ] stats script prints table; Tag `v0.4`

## Interview notes
PTX as a virtual ISA vs SASS; why PTX has unlimited registers and ptxas allocates; state
spaces; predication vs branching; warp divergence and `bra.uni`; what `.rn` means; generic vs
global addressing (`cvta`); cubin = ELF; what JIT compiling PTX in the driver means
(forward compatibility).
