# TinyCU architecture

```
 .tc source
    │  src/frontend/lexer.cpp      hand-written maximal-munch lexer
    ▼
 tokens
    │  src/frontend/parser.cpp     recursive descent, panic-mode recovery
    ▼
 AST  ──────────────────────────── --emit=ast
    │  src/sema/sema.cpp           types, scopes, implicit casts, diagnostics
    ▼
 typed AST ─────────────────────── --emit=ast (typed)
    │  src/ir/lower.cpp            three-address IR in basic blocks
    ▼
 IR ───────┬────────────────────── --emit=ir           src/ir/verifier.cpp after every step
    │      └─► src/interp          interpreter = test oracle (--interp)
    │  src/opt/*                   -O1 passes (phase 6)
    ▼
 IR (optimized)
    │  src/backend/ptx_emitter.cpp instruction selection, register classes
    ▼
 PTX ISA 7.0 ───────────────────── --emit=ptx / -o k.ptx
    │  ptxas -arch=sm_75 (NVIDIA)  register allocation, scheduling, SASS
    ▼
 cubin (ELF) ── CUDA driver ── GPU
```

All stages live in the static library `tinycu_core`. `src/driver/main.cpp` is a thin CLI on
top. Diagnostics are collected by `DiagEngine`, never thrown.

## PTX backend

### Module and kernels
```
//
// Generated by TinyCU <version>
//

.version 7.0          // PTX ISA 7.0: accepted by every CUDA ≥ 11 driver JIT and ptxas
.target sm_75         // --sm=
.address_size 64

	// .globl	saxpy
.visible .entry saxpy(
	.param .f32 saxpy_param_0,     // float -> .f32, int -> .s32, int*/float* -> .u64
	...
)
{
	.reg .pred 	%p<N>;  .reg .b32 %r<N>;  .reg .f32 %f<N>;  .reg .b64 %rd<N>;
	.shared .align 4 .b8 __shared_buf[1024];   // one per shared array
	...
}
```
All kernels of a file go into one module.

### Register mapping
Every IR vreg gets one PTX virtual register of its class, numbered from 1 in vreg order (like
nvcc, `%r<N>` declares `%r0..%r(N-1)`):

| IR type | PTX class |
|---|---|
| i1 | `%p` (`.pred`) |
| i32 | `%r` (`.b32`) |
| f32 | `%f` (`.f32`) |
| ptr, ptr.shared, i64 | `%rd` (`.b64`) |

The non-SSA IR maps directly: re-assigning a named vreg re-assigns its PTX register. ptxas does
the real register allocation. With comments on (the default; `--no-ptx-comments` turns them
off), instructions that define a source variable are annotated: `mov.u32 %r2, %r7; // %i`.

### Instruction selection
| IR | PTX |
|---|---|
| `param` (i32 / f32) | `ld.param.s32` / `ld.param.f32` |
| `param` (ptr) | `ld.param.u64 %rdA, [k_param_N]; cvta.to.global.u64 %rdB, %rdA;` |
| `sreg tid/ctaid/ntid/nctaid` | `mov.u32 %r, %tid.x` / `%ctaid.x` / `%ntid.x` / `%nctaid.x` |
| `add/sub/mul` i32 | `add.s32` / `sub.s32` / `mul.lo.s32` |
| `add/sub/mul` f32 | `add.rn.f32` / `sub.rn.f32` / `mul.rn.f32` (**`.rn` forbids FMA contraction**) |
| `div/rem` i32 | `div.s32` / `rem.s32` |
| `div` f32 | `div.rn.f32` (IEEE-correct division) |
| `neg` | `neg.s32` / `neg.f32` |
| `cmp` i32 | `setp.{eq,ne,lt,le,gt,ge}.s32` |
| `cmp` f32 | `setp.eq.f32`, **`setp.neu.f32`** for `!=`, `setp.{lt,le,gt,ge}.f32` |
| `and/or/not` i1 | `and.pred` / `or.pred` / `not.pred` |
| `cvt.f32.i32` / `cvt.i32.f32` | `cvt.rn.f32.s32` / `cvt.rzi.s32.f32` |
| `min/max/abs` | `min.s32 max.s32 abs.s32` / `min.f32 max.f32 abs.f32` |
| `sqrt` | `sqrt.rn.f32` |
| `mov` | `mov.u32` / `mov.f32` / `mov.pred` / `mov.u64`; a constant i1 is `setp.ne.u32 %p, 1|0, 0` |
| `addr` | `mul.wide.s32 %rdT, %idx, 4; add.s64 %rdA, %rdBase, %rdT;` |
| `load` / `store` | `ld.{global,shared}.{s32,f32}` / `st.{global,shared}.{s32,f32}` |
| shared base `@buf` | `mov.u64 %rd, __shared_buf;` |
| `barrier` | `bar.sync 0;` |
| `br` | `bra.uni L;`, or nothing if `L` is the next block (fall-through) |
| `condbr p, T, F` | `@p bra T; bra.uni F;`, `@!p bra F;` when T falls through; a constant condition becomes a plain `bra.uni` |
| `ret` | `ret;` |

- **Immediates.** i32 is written in decimal and f32 as the exact bit pattern `0f3F800000` (no
  decimal round-trip). ptxas accepts immediates in either source position. Two exceptions get a
  register via `mov`: the index of `mul.wide` (made a register for uniformity) and predicate
  constants.
- **Labels.** IR `if.then.1` becomes `$L__if_then_1` (PTX identifiers can't contain `.`).

### Why `.rn`?
With no rounding modifier, ptxas may fuse `mul.f32` + `add.f32` into one `fma.rn.f32`, which
rounds once instead of twice. The result can differ in the last bit from the interpreter (and
from C semantics). An explicit `.rn` on `add/sub/mul` tells ptxas not to contract. The SASS
confirms it: saxpy compiles to `FMUL` + `FADD`, not `FFMA`. Bit-exact GPU vs interpreter results
depend on this.

## GPU runtime and test paths

```
 tests/kernels/k.tc ──tinycu──► k.ptx ──┬─ CuPy RawModule (python)   ─┐
                                         └─ tinycu-run (C++ Driver API)┤
 tests/kernels/k.cu ──NVRTC -fmad=false──► twin kernel                ├─► bit-exact compare
 tests/kernels/k.tc ──tinycu --interp──► interpreter outputs          │   (tcharness.suite)
 tcharness/references.py ──NumPy──► reference outputs ─────────────────┘
```

- **`tinycu-run`** (`src/runtime/tinycu_run.cpp`, built when CMake finds the CUDA toolkit):
  `cuInit → cuDeviceGet → cuDevicePrimaryCtxRetain → cuModuleLoadDataEx` (with the JIT error log
  buffer, so a bad PTX prints the driver's message) `→ cuModuleGetFunction → cuMemAlloc /
  cuMemcpyHtoD → cuLaunchKernel → cuCtxSynchronize → cuMemcpyDtoH`. Every call goes through
  `CHECK_CU`, which prints `cuGetErrorName`. `--time` reports the median and minimum of 20
  `cuEvent` timings. Input and output JSON use the same format as `tinycu --interp`.
- **`tcharness.suite`** loads each `tests/kernels/<k>.json` spec, generates deterministic inputs
  (the seed comes from the kernel name and n), and runs the paths `interp`, `gpu` (CuPy, falling
  back to `tinycu-run`) and `nvrtc`. Every path is compared bit-exactly with the NumPy
  reference.
- **Kernel suite:** 22 kernels covering int/float arithmetic, wrap-around, branches, every loop
  form, a grid-stride loop, shared memory with barriers, matmul and a stencil. Sizes include
  non-multiples of the block size. Each kernel has a CUDA twin; twins use `unsigned` where TinyCU
  relies on wrap-around, because signed overflow is UB in CUDA C++.

## Tooling
- `tools/ptx_check.sh k.ptx [sm]` runs `ptxas -v` and prints registers, spill bytes and shared
  memory per kernel.
- `tools/ptx_validate.sh [tinycu] [sm]` compiles every valid test program at `-O0` and `-O1` and
  requires ptxas to accept all of them (CI job `ptx-validate`).
- `python -m tcharness.ptxstats [--opt N] [--out file.md]` builds a table of PTX instructions,
  registers, spills, smem and SASS instructions per kernel (from `cuobjdump -sass`, excluding NOP
  and the trailing self-`BRA` padding), plus the cubin ELF sections.
